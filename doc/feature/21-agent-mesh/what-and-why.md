## 0. 摘要

**本文的锚点：三层结构**

| 层 | 是什么 | 能否集中 | 属性 |
|---|---|---|---|
| **大脑**（推理） | 云 LLM / 本地 LLM | ✅ 能，且正在被商品化 | 可替换、可升级、按 token 计费 |
| **身体**（执行） | 主机上的 CPU / IO / 硬件 / 数据 / 网络位置 / 凭证 | ❌ **不能**，物理上就是分散的 | 稀缺、不可迁移 |
| **神经系统**（mesh） | 把**意图**送到能干活的身体，把**结果**带回来 | —— | **本特性所在的那一层** |

**三句话**

1. **是什么**：作用在 DSH 之上的**跨主机智能体通信层** —— 同一个人的多台机器上的 agent 能互相发现、互相派活、互相问答（端到端加密，人可见、可控、可叫停）。
2. **根论证**：**推理可以集中，行动必须就地** —— token 搬不到数据、硬件与权限所在的地方，只有 agent 能。云 LLM 越强，这一条越成立。
3. **值多少**：价值是**结构性**的，且**随主机数增长** —— 它决定产品是"更好的远程桌面"还是"私有的 agent 集群"。

## 1. What —— 它是什么

**一句话定义**：让**同一账号下、不同主机上的 DSH agent** 能够互相发现、互相派活、互相问答；消息复用既有出站隧道中转、**端到端加密**（hub 只看到"谁发给谁、何时、多大"），人全程可见、可控、可叫停。

**三件能力**（工具面；需求与验收标准见 `req.md` R1–R7）：

| 能力 | 做什么 | 一句话 |
|---|---|---|
| **发现** | `list_peers` | 列出同一账号内已开启 mesh 的其他主机（名称、在线、能力标签） |
| **投递** | `send_to_peer` | 把一段内容交给对端 agent，拿到"已接收"确认 |
| **请求-应答** | `ask_remote` | 派活并取回结果：快任务直接返回，超 60s 转 job（可等待、看进度、能叫停） |

**物理形态**：host 侧是一个**新的 DSH 插件**（`dsh-agent-mesh`，装在"隧道持有者那个 dsh 实例"里）；hub 侧是**加法式**新增（agent 索引 + 投递 API）；**不建隧道、不抢 `join.lock`、不改线协议、不改 gateway 转发**（D3/D8/D9）。

**术语表**：

| 术语 | 含义 |
|---|---|
| **peer** | 同一 owner 下、已开启 mesh 的另一台 host |
| **AgentCard** | host 侧上报的能力卡（名称 + 在线 + 能力标签），仅同 owner 可见（D14/D16） |
| **收件会话** | 对端**专用**的 DSH 会话，承载入站请求；**绝不**插入人类正在使用的会话（D16） |
| **信封（AgentMessage）** | `{from, to, type, payload, correlationId, security}`；hub 只读路由字段，`payload` 端到端加密（D10/D25） |
| **correlationId** | 一次请求-应答的关联键，兼作幂等去重键 |
| **job** | 超过同步等待上限的跨主机任务，在发起侧落成的可等待句柄（D21） |

## 2. What it is NOT —— 划界

### 2.1 与最容易混淆的相邻概念

| 它不是 | 因为 |
|---|---|
| **远程访问**（现有能力） | 那是"人操控 UI"（L2）；mesh 是 **agent↔agent**，且只给 **L0（消息）** |
| **共享会话 / 上下文** | 会话保持主机本地，跨主机**只传消息**（D12） |
| **消息总线 / 订阅** | 没有 topic / retention / 位点语义；总线另立特性 `22-agent-bus`（D24） |
| **给 agent 一台机器的访问权** | agent 永不获得 L1/L2；要进整台机器必须由人显式 `host_share`（D13） |
| **新的隧道 / 新协议 / 新端口** | 复用既有出站隧道与 hub 转发，**线协议字节级零改动**，不需要公网 IP（D3/D8） |
| **跨账号互联** | 仅同 owner；跨账号一律拒绝，且共享成员不入 mesh（D20/D17） |
| **多跳组网** | 仅单跳（A→B；A→B→C 不允许）（D18） |

> 产品含义：mesh **不扩大**任何人对任何机器的访问权，它只是让**已经属于你的**那些机器之间多一条 message 通道。

### 2.2 与相邻生态的区别（社会模拟 / agent 社交平台 / 多智能体框架）

"把多个 agent 放进社交网络让它们互相聊天"是真实存在的类别（代表：Moltbook —— OpenClaw 2026-01 做的 AI-only Reddit，人类只读；更早有 Stanford Generative Agents / Smallville、AI Town、OASIS）。它其实混了**三类**不同的东西：

| 类别 | 代表 | 目的 | 环境 |
|---|---|---|---|
| **社会模拟** | Generative Agents / Smallville、AI Town、OASIS | 研究、观察**涌现行为** | 沙盒；行为无外部后果 |
| **Agent 社交平台** | Moltbook、Chirper | 展示/表演"agent 之间会聊什么" | **公共平台**；陌生账号多对多；人类只读 |
| **多智能体框架** | CAMEL / AutoGen / ChatDev / crewAI | 在**一个编排内**协作解题 | 单进程/单机；无网络与信任问题 |
| **本特性** | agent mesh | 让**你自己的活**跨机器完成、结果回到你的会话 | **私有**：同 owner、通常 2–5 台机器的闭集 |

**一句话定位**：他们造的是"**社会**"（模拟或表演），我们造的是"**工具**"（你机器的私有 agent 网络）。

三条根上的差异：

1. **消息有没有后果**。那边一条消息的全部后果是多一个帖子/一个赞；我们一条消息能让对端跑 40 分钟构建、改文件、烧掉额度。D10/D13/D19/R16 全是被"**有后果**"逼出来的 —— 他们不需要这些。
2. **闭集有主 vs 公海无主**。他们解决"**陌生人之间**怎么互动"，信任来自平台裁决（Moltbook 靠发帖节奏、会话模式、注册自述判定"你是不是人"）；我们解决"**我自己的机器之间**怎么安全派活"，信任来自密码学身份（host 密钥 + Ed25519 签名）+ `owner_id` 相等。这正是我们**不做**跨账号、总线/订阅、公共 feed 的原因。
3. **工具 vs 社会**。他们赌"自由互动会涌现出有趣的东西"；我们做的是**可验证的委托**（correlationId 对账、超时转 job、可取消、有审计）。真要"涌现协作"，需要记忆流、反思、关系、声誉 —— 那是另一类产品，也是我们刻意排除的部分。

**与多智能体框架不是竞争关系**：我们是它们可以跑在其上的**网络层**（传输 + 身份 + 信任）。完全可以在 B 机跑一个 AutoGen/crewAI 编排，A 机只发一个意图过去。

**值得从他们那里学的坑**（我们已在不同程度上预防）：

- **环与风暴**：agent 互相回复会无限放大 ⇒ 我们的 `reply 永不触发新的 ask` + 每对 peer 限速熔断（D18）；
- **成本失控**：Moltbook 72 小时 18 万帖，大头是"关于平台自身的元讨论" ⇒ 我们只向显式目标投递、不做环境性闲聊；
- **唤醒与持久化**：他们用 email 收件箱当持久层（agent 离线几小时，回来收摘要再回）⇒ 对应我们的收件会话（D16）与未来 P4 的离线队列；
- **身份冒充**：他们靠行为特征判人，我们靠签名 —— 更硬，但**密钥生命周期**必须管好（D11/R15）。

> 外部资料（**未独立核实**，仅作对照，按外部数据看待）：Moltbook 的规模与架构见 [Inbounter 的说明](https://inbounter.com/blog/openclaw-moltbook)；社会模拟这一支的脉络见 [OASIS 论文解读](https://github.com/xyskywalker/Ripple/blob/main/docs/paper-reviews/OASIS-open-agent-social-interaction-simulations.md)。

## 3. 根论证：大脑在云，身体在端

### 3.1 为什么必须是"分布式"agent

**推理可以集中，行动必须就地。** 云 LLM 是一个纯函数：给它上下文它给文本，它**没有手**。要让事情真的发生——改文件、跑构建、按快门、驱动电机——必须有一个"**身体**"在那个地方。

关键的物理事实：**token 搬不到数据、硬件与权限所在的地方，只有 agent 能。** 所以"分布式 agent"不是一个架构选择，而是**执行这件事本身的形状**；mesh 就是这一层"神经系统"。

### 3.2 为什么云 LLM 越强，分布式 agent 越必要

1. **智能变便宜 ⇒ 任务变多（Jevons 式）**。token 单价下降不会让人少用 agent，只会让更多人愿意把更多事交出去 —— 而瓶颈从来不是"想"，是"**做**"。
2. **本地动作循环比远程操控省 token**。人肉远程操控等于"每一步都模型往返"；把 agent 放到那台机器上，它能在本地连跑 50 条命令，只在首尾交换一次意图与结果。**mesh 传的是意图（小），不是步骤（多）。**
3. **隐私靠拓扑解决**：数据留在原地，只有结论出走；叠加 E2EE 后连 hub 都只看得到路由元数据。

### 3.3 "住在主机上"买到了什么（= 能力标签该表达的东西）

| # | 能力 | 说明 |
|---|---|---|
| 1 | **数据引力与隐私** | 仓库、数据库、照片、邮件、凭证、临床/法务资料；搬 2 TB 不如搬 agent，有些数据**永远不该出主机** |
| 2 | **算力与加速器** | GPU（本地推理/微调/渲染）、大磁盘、编译农场、授权软件 |
| 3 | **IO / 硬件 / 传感器** | 摄像头、串口/USB、GPIO、打印机、示波器、机械臂 —— **云根本替代不了**的那一支 |
| 4 | **网络位置** | 某个 LAN/VPC 内、白名单 IP、只能内网访问的服务 —— 网络拓扑本身就是能力 |
| 5 | **凭证与权限** | 那台机器持有的 token/密钥；mesh 的价值恰恰是**不搬运凭证**，只搬运消息 |
| 6 | **常在性与时间** | 常开的机器可以你睡觉时干活、盯事件、保持状态 |
| 7 | **成本与主权** | 本地 GPU 够强就本地跑（高频低风险循环用本地模型、罕见硬推理上云）；省钱 + 离线可用 + 数据不出门 |

### 3.4 不是所有任务都需要身体

研究、总结、起草、写代码草稿这类**纯信息任务**，云里做完全够。mesh 的价值集中在**有副作用**的任务上：落盘、构建、动设备、用凭证、占机器。

⇒ 所以"**能力差**"决定 mesh 值多少：笔记本自己也能干的事，mesh 加成很小；只有当 GPU / 设备 / 数据 / 网络位置 / 常在性上的差距真实存在时，它才不可替代。

### 3.5 替代压力，以及这条轴的真实含义

- **云沙箱（别人的电脑）**能替掉相当一部分"执行"需求（托管开发环境、CI、云 VM）。它替不掉的是：**你自己的私有数据、硬件、凭证、网络位置、规模成本、主权** —— 这正是 remote-dsh 坚持"私有 + 自托管 + 只出站 + 无公网 IP"的意义。
- 更锋利的一句：**这条轴不是"边缘 vs 云"，而是"权威所在之处"**。你租的云 VM 也是一个身体（有它的网络位置与凭证）。mesh 的路由目标是"**哪里有权限和数据**"，不管那是你的笔记本、NAS，还是你的云主机。
- **机器人 / 嵌入式**：长期想象空间最大，但它是**独立的产品面**（实时性、安全、硬件协议、物理失败不可回滚）。近端版本是那些平淡但真实的东西：NAS、家庭服务器、打印机、摄像头、3D 打印机、树莓派 GPIO。设计上只需保证它能长成那样 —— **mesh 永远不需要知道那个身体是什么**。

## 4. 直接价值：人是总线 → agent 是总线

今天跨机器做事的唯一通路是**人**：切到另一台机器的界面、在那边另开一个会话、把上下文口述过去、再把结果搬回来 —— **人承担了传输与协调的全部工作**。mesh 换掉这条假设，人从"操作每台机器"上升为"**给意图 + 验收结果**"。

> 类比：今天每台机器是一座带吊桥的岛，你亲自过桥；mesh 之后它们是**同一个生物的不同肢体** —— 大脑（你所在的会话）指挥离活最近的那条肢体。

| 场景 | 今天 | 有了 mesh |
|---|---|---|
| **工作的机器 ≠ 思考的机器** | 切到 B 的 UI，A 的会话线索断掉，回来还要复述结果 | 在 A 的会话里说一句，结果回到 A —— **上下文不搬家** |
| **长任务落到对的机器**（GPU / 大磁盘 / 只在那边有的仓库 / 特定网络） | 得在那边守着，或手动轮询 | 派过去 → 转 job → 节流进度 → 随时叫停（D21） |
| **N 台机器汇总一件事**（各机分支、磁盘、哪台测过） | N 次手动会话 | 一次广播 + 散射-收集，逐台结果、单台失败不拖累整体（R14） |
| **人不在键盘前** | 基本无解 | 手机上让常开的机器干活（服务器成为"值班机"） |
| **机器专业化** | 每台都得人肉照顾 | 笔记本当瘦终端、工作站出算力、服务器常开 —— 按能力派活（P4） |

一句话：**今天是"远程桌面 ×N"，mesh 之后是"一个可以对话的集群"。** 一台机器的集群毫无意义；三台以上并且有分工时，性质就变了。

## 5. 产品价值（对 remote-dsh 本身，可能比功能价值更重要）

1. **类别跃迁**：现有定位是"安全远程访问层"，本质与 Tailscale + 浏览器同类，护城河不深；mesh 把它推向"**你自己机器的私有 agent 网络 / 编排层**"。
2. **存量资产变现**：护城河不在"能连上"，而在"**同一 owner 信任模型 + 只出站隧道 + 端到端加密 + agent 原生派活**"这套组合 —— 而这些**已经建好了**（host 身份密钥、hub 的 owner 判定、E2EE 原语、隧道）。mesh 是把存量用起来，不是另起一摊。
3. **让多主机付费成立**：今天 N 台机器只等于 N 个互不相干的入口，"为第 3 台付费"的理由很弱。mesh 是**第一个价值随主机数增长**的特性，正好接上现有的按主机配额模型。
4. **治理模型顺带成型**：D15 的"可见 + 可叫停"就是"人给意图、机器执行"这一形态的治理答案 —— 它是产品走向更高自主性时必须先有的东西。

## 6. 诚实的边界（什么时候它不值）

不吹的部分，必须和上面写在一起：

- **短任务 + 键盘在手时，切标签页更便宜**。走 agent 往返要付两边的 token、协调开销与延迟。
- **频率可能并不高**。2 台机器的个人用户，真实需求也许每周几次 —— 这正是"interesting but not urgent"的根源：**痛点存在但可忍受**（手动切过去也能干）。
- **替代品很便宜**。SSH + cron + rsync 覆盖的是跨机器的**机制**（命令级）；mesh 给的是跨机器的**判断力**（意图级）—— 对端有上下文、能自己决定怎么做。若需求只是执行命令，SSH 就够了。
- **新增攻击面**。每条 agent↔agent 通路都是"被带偏的 agent 去指挥另一台机器"的潜在通道。我们压到 L0 + 方向/能力上限 + 可信头（R16），但这是**因为这个特性才存在**的代价。
- **上游风险**。若 DSH 官方自己做了多机 / 多 agent 编排，这块价值会蒸发一部分。

## 7. 时机：什么时候从"有趣"变成"必须做"

按杠杆排序（前两条出现就该动手，后三条决定它能走多远）：

1. **主机数 ≥3 且有真实分工**（算力机 / 常开服务器 / 瘦终端）—— 单机时这个特性等于不存在。
2. **长任务**：人无法全程盯着，必须"派出去 + 看进度 + 能叫停"。
3. **手机端**：不在键盘前时价值陡增。
4. **定时 / 事件触发**（夜里跑、有事才跑）—— 依赖 P4 的离线队列，否则 mesh 只是交互式的。
5. **能力路由**（"谁会做 X"自动选机）—— 把 peer 列表变成**系统**的质变点。

**价值归零的条件**（四条同时成立时，这就是"一个在找用户的功能"）：长期只用一台机器 / 任务都很短 / 永远在键盘前 / 上游自己做了。

**最灵敏的触发信号**（出现任一即说明痛点越线）：

- 你开始**频繁在"两个会话之间人肉倒信息"**；
- 你想**在手机上派一个长任务然后走开**。

## 8. 推进方式与反向决策

1. **杠杆顺序**：**P0（发现）→ P1（单条 E2EE 投递 + 长任务语义）**。这两步就能产生"哇"的瞬间；**P1.5/P2.5 的广播是 P1 之上最便宜的倍增器**（复用逐对加密与本地扇出，成本≈0）。
2. **不要为了"看起来完整"提前做**：拓扑界面、总线/订阅、能力路由都属于"价值随规模出现"的东西，早做就是负担（见 `req.md` §2 非目标、`discussion.md` §10）。
3. **本文的反向用法**：排期争论时，如果某个待做项既不服务于 §7 的五个驱动、也不增强 §5 的资产，那它大概率可以被砍。

## 9. 本论证对设计的含义

1. **能力标签的重心是"身体有什么"**（数据 / 加速器 / 设备 / 网络位置 / 常在性），不是"模型会什么" —— 这让 P4 能力路由具体且可评测（对应 §3.3）。
2. **body-agnostic 是硬架构要求**：mesh 只送意图，"能不能干、怎么干"由 host 自己决定 —— 同一套设计要能覆盖 Mac、NAS、树莓派，将来还有机器人。
3. **离线与主权场景提高 P4 离线队列的价值**：对端是自托管、甚至半离线时，投递语义不能只靠"当时在线"（D22 → P4）。
4. **手机也是身体，方向是双向的**：手机有摄像头、麦克风、定位、通知 —— 不只是"笔记本派活给工作站"，也可以是"工作站让手机拍一张 / 提醒一下"。这是移动端从"遥控器"变成"节点"的转变。
5. **明确不做**：**不把 mesh 做成分布式计算 / GPU 调度平台**（Ray / K8s 那一类）。我们的赌注只有四件东西：**身份、权限、消息、审计**，加上能力标签做路由；其余交给 host 自己。
