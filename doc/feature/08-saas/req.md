## 1. 目标

让用户**自助注册（邮箱或 +86 手机号）→ 验证 → 试用 → 付费订阅**托管 hub：运营方按"host 数 × 订阅时长"收费（招行聚合收款，微信/支付宝扫码），试用 3 天 1 host 拉新。**注册标识符双通道**：邮箱为全球惯例；**+86 手机号+短信验证码**为中国主流（几乎人人有手机号，相当比例用户不常用邮箱）；登录形态统一为"标识符 + 密码"，短信码仅用于注册验证/绑定/找回。**自托管形态不变（开源免费）**；SaaS 是托管服务形态。**北极星：用户免部署，任何地方（电脑/手机浏览器）直接使用 DSH。**

**定位事实**：资质基本已具备（公司主体 + 招行对公户 + ICP 备案 + 川 B2 证，2026-08-26 核验）；剩余为招行聚合收款签约与 B2 证覆盖类目确认（见 §5），不阻塞 S1/S2 开发。

## 2. 范围

### 2.1 包含（In Scope）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| R1 | **开放注册（双通道）+ 验证**：`POST /api/auth/register {channel: "email"\|"phone", identifier, password}` → 邮箱通道发 6 位 PIN（**复用 M5 邮件基建**：10 分钟、重发限流）；手机号通道发 6 位短信码（**新增 `SmsSender` 抽象镜像 `EmailSender`**：aliyun/log provider、mock 先行；**开关 = hub.json `sms` 配置节，缺省关闭**，与 `email` 同语义）→ `POST /api/auth/verify {channel, identifier, code}` 激活；**+86 手机号格式校验**（11 位）；**注册开关可配置**（SaaS 开 / 自托管关，复用同一代码路径） | 邮箱注册→收 PIN→验证→可登录；手机号注册→收短信码→验证→可登录；**未配置 `sms` → 手机号通道整体不可用并明确提示"未启用"**；未验证不能加 host；重发限流；非法手机号拒绝；开关切换生效 |
| R2 | **试用**：验证（邮箱或手机号任一）后自动进入试用：**1 台 host 配额、3 天**；portal 显示试用剩余时间；**试用到期 → 3 天 grace → 降级免费档（0 台，按 R6）** | 验证后可用；第 2 台 host 注册被拒（配额错误码）；到期进 grace；grace 到期降级 0 台 |
| R3 | **配额钩子消费**：`POST /api/hosts/register`（join token 主机注册，05 预留钩子）按账号 plan 检查 host 数上限；配额表/配置可改；**plan=NULL（存量/自托管/admin）不受限** | 免费/试用/付费档配额不同；超限返回明确错误；存量用户不受限 |
| R4 | **订阅与套餐**：`subscriptions`/`orders`/`payments` 表；套餐模型 host 数 × 时长（价格 config 可配）；**默认占位价（2026-08-26 中开策略，S1 数据校准）**：Pro 5 台 ¥39/月、Team 20 台 ¥99/月（战略锚 $20/月 ≈ ¥145；对齐 Coze ¥39.9/¥99 与远控团队 ¥98–199）；`GET /api/billing/plans`、`POST /api/billing/subscribe {planId}` | 套餐列表；订阅创建订单；配额按订阅生效 |
| R5 | **支付（招行聚合收款）**：订阅 → 生成支付单 → 支付形态**按设备自适应**：桌面 = 聚合二维码（手机扫码）；手机浏览器/微信内浏览器 = **直唤起微信/支付宝 App 完成支付**（JSAPI/H5，待招行确认支持）；**异步回调验签（国密 SM2/SM3）+ 幂等入账**；订单状态机（created→paid→closed）；对账任务（日终核对）。`PaymentProvider` 抽象（mock 先行，复用 M5 EmailSender 模式） | mock 全流程走通；招行沙箱（资质到位后）；**手机浏览器与微信内浏览器直唤起支付验收**；回调重复通知只入账一次；验签失败拒绝；对账报告 |
| R6 | **到期/降级/数据保留**：试用或订阅到期 → **3 天 grace**（portal 提示，隧道保留）→ 降级**免费档（0 台）**：全部 host 离线、数据保留 **30 天**；**换到更低配额档时保留最早注册的 N 台在线、其余离线**；超期 host 数据删除（可配置） | 状态机各阶段行为正确；portal 明确提示 |
| R7 | **账号删除（合规）**：用户自助删除账号 → 立即停隧道 + 删个人数据（邮箱/手机号/hosts/隧道全删）；`payments`+`orders` 保留**脱敏账务必要字段**（金额/时间/渠道单号），审计留痕 | 删除后可再次注册；审计留痕 |
| R8 | **反滥用**：注册/发码前置**阿里云验证码 2.0**（滑块验证：前端 SDK + 后端 VerifyCaptcha 验签，复用 AccessKey RPC 签名，免费额度+按量；M5 算术码为找回密码兜底）+ 限流（IP+邮箱域名）；**短信防轰炸**（每手机号每日 ≤3 条、全局上限、重发 60s、验证码 attempts ≤5——短信有成本，比 email 更严）；试用多账号风控（MVP：同 IP 30 天内限 2 个试用账号、**同手机号限 1 个试用账号**——手机号比邮箱稀缺，天然抗 bot）；`banned` 状态 | 机器人注册被挡；薅试用被限；短信轰炸被挡；**滑块验证不通过不发码**；封禁生效 |
| R9 | **安全强化（依赖 07）**：登录风控账户锁定、2FA（可选开启）、付费操作审计（订阅/支付/退款） | 07 验收项在 SaaS 端到端复验；付费操作均有审计事件 |
| R10 | **portal 商业化页面**：注册/验证页（**邮箱\|手机号双 tab**，`sms` 关闭时手机号 tab 隐藏）、登录页（邮箱/手机号统一输入 + 智能解析）、试用倒计时、套餐选择、订阅状态、支付回调页、发票/退款入口（MVP 退款自助、发票占位说明）、**手机号绑定入口**（`sms` 关闭时隐藏）、**找回密码双通道入口**、账号删除（**文本 UI 稿见 §2.6**） | 全流程浏览器可操作；i18n zh/en |
| R11 | **手机号管理 + 找回密码**（**`sms` 关闭时整体不可用**）：账号设置绑定/换绑手机号（**复用 M5 邮箱绑定路径**：绑定→发短信码→验证，**发码前置滑块验证（R8）**；换绑重验；解绑后 24h 内不能重绑）；**找回密码双通道**：邮箱找回（M5 已有）+ 手机号短信码找回（复用同一「设新密码→ver+1」路径，触发页带算术验证码防 bot） | 绑定→收短信码→验证成功；换绑成功；解绑后 24h 内重绑被拒；手机号找回全流程走通；改密后旧会话 401；**`sms` 关闭时各入口明确提示"未启用"** |

### 2.5 账号状态机（两维分离，2026-08-26 定案）

> 账号维度（能否登录/存在）与计费维度（host 配额）分离：配额钩子只读 `plan_status`，封禁/删除只读 `account_status`，互不耦合。

**account_status**（users 表）：

| 状态 | 含义 | 出迁 |
|---|---|---|
| `pending` | 注册未验证 | verify 通过 → `active` |
| `active` | 已验证可用 | 封禁 → `banned`；自助删除 → `deleted` |
| `banned` | 反滥用封禁（立即停隧道 + 禁登录） | admin 解封 → `active`（恢复原 plan_status） |
| `deleted` | 终态 | — |

**plan_status**（users 表；`NULL` = 不受限）：

| 状态 | 配额 | 出迁 |
|---|---|---|
| `NULL` | 不限（存量/自托管/admin 建号） | — |
| `trial` | 1 host × 3 天 | 到期 → `grace`；提前付费 → `subscribed` |
| `subscribed` | 套餐 N × 时长 | 到期 → `grace` |
| `grace` | 原配额保留（挽留） | 3 天 → `free`；续费 → `subscribed` |
| `free` | 0 host（离线 host 数据保留 30 天） | 重新订阅 → `subscribed` |

**配套规则**：

- 30 天数据保留 = 降级到 `free` 后对离线 host 数据的定时清理，**非 plan 状态迁移**；清理后账号仍在 `free`；
- 提前付费（trial 中订阅）直接切 `subscribed`，剩余 trial 时长不叠加；
- 解封（banned→active）恢复原 plan_status，不重发试用；
- 存量自托管用户 plan_status 保持 `NULL`（不受限），仅新注册进 `trial`。

```
│  → 收码 → 设新密码 → 旧会话全部失效   │
└──────────────────────────────────────┘
```

## 3. 端到端验收场景

1. **注册→试用（双通道）**：新用户邮箱注册 → 收 PIN → 验证 → 自动进入试用（portal 显示 3 天倒计时 + 1 host 配额）→ 加 1 台 host 成功 → 加第 2 台被拒；**手机号通道同样走一遍**（收短信码 → 验证 → 试用 → 第 2 台被拒）
2. **付费**：选择套餐 → 微信/支付宝沙箱支付 → 回调入账 → 订阅激活 → 配额升级到套餐档 → 可加更多 host
3. **到期降级**：试用或订阅到期 → grace 3 天（隧道保留、portal 提示）→ 降级免费档（0 台）→ 全部 host 离线、数据保留 30 天 → portal 可见保留期
4. **反滥用**：同 IP 第 3 个试用账号被拒；机器人注册被 PIN/限流挡
5. **删除**：用户删除账号 → 隧道立停、数据清除、可重新注册
6. **审计**：订阅/支付/退款操作在 `rdsh hub audit ls` 可查
6b. **找回密码（手机号）**：绑定手机号 → 忘记密码 → 收短信码 → 设新密码 → 旧会话全部失效
7. **回归**：07 全量验收 + 自托管形态（注册关闭）不受影响

## 4. 验收执行方式

- 自动化：`node --test`（PIN/注册/配额/订阅状态机/支付回调验签与幂等/对账/反滥用/删除）
- 支付：微信/支付宝**沙箱**联调；生产商户号资质到位后灰度
- 短信：SmsSender log/mock 单测（不发真短信）；阿里云短信签名/模板审核到位后真发冒烟
- 回归：`pnpm test` 全量 + 自托管形态 e2e
- 文档：`verification.md` RTTM

## 6. 技术约束备忘

- **幂等**：支付回调、订阅激活、配额检查全部幂等；对账任务兜底
- **协议先行**：新增层 1 API（register/verify/billing/subscribe/callback）契约文档先行
- **依赖**：支付 SDK/验签、阿里云短信（SDK 或手写 RPC 签名，参照 M5 邮件 aliyun 做法）为合理例外；其余延续零依赖纪律
- **安全**：PIN/重置码/短信码/支付密钥不落明文（sha256 存储）；日志脱敏（手机号/邮箱）；回调端点限流 + 审计；**手机号存 E.164 规范格式（+86）**
- **短信**：`SmsSender` 抽象镜像 `EmailSender`（aliyun/log provider，mock 先行）；防轰炸限流（每手机号每日 ≤3 条 + 全局上限 + 重发 60s + attempts ≤5）
- **验证码防 bot**：注册/绑定发码前置**阿里云验证码 2.0**（前端 SDK + 后端 VerifyCaptcha 验签，复用 AccessKey RPC 签名；免费额度+按量，额度/单价待查证）；找回密码保留 M5 算术码（零依赖）
- **开关**：`sms` 配置节**缺省关闭**（与 `email` 同语义：未配置 = 手机号通道整体不可用，注册/绑定/找回返回"未启用"）；**默认关闭直到阿里云签名/模板审核通过再开启**（成本 + 资质双控）
