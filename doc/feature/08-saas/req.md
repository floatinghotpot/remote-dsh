# 08-saas — 需求（req.md）

> **日期**: 2026-08-24
> **状态**: 草稿，**待用户批准**
> **范围**: 商业化托管 hub（SaaS 形态）—— 开放注册+邮箱验证、试用、配额、订阅计费、支付（微信/支付宝）
> **来源**: [discussion.md](discussion.md)（D1–D10 定案）：email 即用户名、试用 3 天 1 host、定价模型 host 数×时长（价格可配置）、状态机 trial→grace(3d)→降级→保留 X 天→删除、支付需商户号（企业资质）、E2E 加密为 P0 并行子项、注册开放可配置、反滥用 PIN+限流、MVP SQLite+备份、退款 7 天/发票后置
> **前置依赖**: **07-multi-tenant（M5）**：email/2FA/审计/登录风控（本里程碑的账号安全底座）；资质办理（支付商户号/EDI）与 M6 并行

---

## 1. 目标

让用户**自助注册 → 邮箱验证 → 试用 → 付费订阅**托管 hub：运营方按"host 数 × 订阅时长"收费（微信/支付宝），试用 3 天 1 host 拉新。**自托管形态不变（开源免费）**；SaaS 是托管服务形态。

**定位事实**：商业化的真正瓶颈在资质（支付商户号需企业资质、经营性 ICP/EDI）——本管线实现技术，资质办理并行启动（D5/D6，见 §5）。

## 2. 范围

### 2.1 包含（In Scope）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| R1 | **开放注册 + 邮箱 PIN 验证**：`POST /api/auth/register {email, password}` → 发 6 位 PIN（10 分钟、重发限流）→ `verify` 激活；**注册开关可配置**（SaaS 开 / 自托管关，复用同一代码路径） | 注册→收 PIN→验证→可登录；未验证不能加 host；重发限流；开关切换生效 |
| R2 | **试用**：邮箱验证后自动进入试用：**1 台 host 配额、3 天**；portal 显示试用剩余时间 | 验证后可用；第 2 台 host 注册被拒（配额错误码）；到期后按 R6 规则 |
| R3 | **配额钩子消费**：register 端点（05 预留钩子）按账号 plan 检查 host 数上限；配额表/配置可改 | 免费/试用/付费档配额不同；超限返回明确错误 |
| R4 | **订阅与套餐**：`subscriptions`/`orders`/`payments` 表；套餐模型 host 数 × 时长（价格 config 可配）；`POST /api/billing/plans`、`POST /api/billing/subscribe {planId}` | 套餐列表；订阅创建订单；配额按订阅生效 |
| R5 | **支付（微信/支付宝）**：订阅 → 生成支付单 → 跳收银台；**异步回调验签 + 幂等入账**；订单状态机（created→paid→closed）；对账任务（日终核对） | 沙箱全流程；回调重复通知只入账一次；验签失败拒绝；对账报告 |
| R6 | **到期/降级/数据保留**：订阅到期 → **3 天 grace**（portal 提示，隧道保留）→ 降级免费档（超出配额 host 离线但数据保留 **30 天**）→ 超期删除（可配置） | 状态机各阶段行为正确；portal 明确提示 |
| R7 | **账号删除（合规）**：用户自助删除账号 → 立即停隧道 + 删用户数据（host/订阅/支付记录保留账务必要字段） | 删除后可再次注册；审计留痕 |
| R8 | **反滥用**：注册 PIN + 限流（IP+邮箱域名）；试用多账号风控（同 IP/设备指纹记录，MVP 规则简单：同 IP 30 天内限 2 个试用账号）；`banned` 状态 | 机器人注册被挡；薅试用被限；封禁生效 |
| R9 | **安全强化（依赖 07）**：登录风控账户锁定、2FA（可选开启）、付费操作审计（订阅/支付/退款） | 07 验收项在 SaaS 端到端复验；付费操作均有审计事件 |
| R10 | **portal 商业化页面**：注册/验证页、试用倒计时、套餐选择、订阅状态、支付回调页、发票/退款入口（MVP 退款自助、发票占位说明）、账号删除 | 全流程浏览器可操作；i18n zh/en |

### 2.2 不含（Out of Scope）

- ❌ **E2E 加密（Q5）** → **并行独立立项（P0）**：公共 SaaS 必须，不在本管线内实现（协议位已预留，见 08-discussion §3.2-⑦）
- ❌ 发票开票（数电票对接）→ 后置（MVP 只退款不开发票，页面声明）
- ❌ 图形验证码 → 后置（PIN+限流先挡）
- ❌ PostgreSQL 迁移 → 评估项（MVP SQLite + 每日备份）
- ❌ 优惠券/促销/渠道分销 → 后置
- ❌ 带宽/存储计量计费（按时长套餐起步）→ 后置

## 3. 端到端验收场景

1. **注册→试用**：新用户邮箱注册 → 收 PIN → 验证 → 自动进入试用（portal 显示 3 天倒计时 + 1 host 配额）→ 加 1 台 host 成功 → 加第 2 台被拒
2. **付费**：选择套餐 → 微信/支付宝沙箱支付 → 回调入账 → 订阅激活 → 配额升级到套餐档 → 可加更多 host
3. **到期降级**：订阅到期 → grace 3 天（隧道保留、portal 提示）→ 降级免费档 → 超出 host 离线、数据保留 30 天 → portal 可见保留期
4. **反滥用**：同 IP 第 3 个试用账号被拒；机器人注册被 PIN/限流挡
5. **删除**：用户删除账号 → 隧道立停、数据清除、可重新注册
6. **审计**：订阅/支付/退款操作在 `rdsh hub audit ls` 可查
7. **回归**：07 全量验收 + 自托管形态（注册关闭）不受影响

## 4. 验收执行方式

- 自动化：`node --test`（PIN/注册/配额/订阅状态机/支付回调验签与幂等/对账/反滥用/删除）
- 支付：微信/支付宝**沙箱**联调；生产商户号资质到位后灰度
- 回归：`pnpm test` 全量 + 自托管形态 e2e
- 文档：`verification.md` RTTM

## 6. 技术约束备忘

- **幂等**：支付回调、订阅激活、配额检查全部幂等；对账任务兜底
- **协议先行**：新增层 1 API（register/verify/billing/subscribe/callback）契约文档先行
- **依赖**：支付 SDK/验签为合理例外；其余延续零依赖纪律
- **安全**：PIN/重置码/支付密钥不落明文；日志脱敏；回调端点限流 + 审计
