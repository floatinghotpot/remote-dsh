## 1. 背景与目标

### 1.1 低门槛阶梯（用户复述，2026-08-26）

目标：让用户**用最少的力气用上智能体**（general-purpose agent / 数字员工 —— **coding 只是已验证的第一个甜点场景，不是边界**；DSH 是 agent harness：命令/文件/工具/工作流，本质"一台电脑 + 一个会干活的智能体"），逐级降低使用门槛：

| 级 | 形态 | 门槛 | 状态 |
|---|---|---|---|
| 1 | 局域网/VPN 远程访问（自带机器） | 装 rdsh + 同网段 | ✅ M1 |
| 2 | 公网 IP 云主机直连（自带机器） | 云服务器 + TLS + 密码 | ✅ M2 |
| 3 | hub 转发，无需公网 IP（自带机器） | 管理员建号 + join | ✅ M3–M5 |
| 4 | 自助注册 + 付费订阅（自带机器） | 账号 + 支付 | 🔄 08-saas（S1–S4） |
| **5** | **云端租用 DSH 环境（不用带机器）** | **注册 + 付费，浏览器即用** | 💡 本文（09） |

### 1.2 09 构想（用户提出）

用户登录 hub 账号，除了接入自己的机器，还可以**动态创建（租用）我们的云资源**，生成**临时或永久**的 DSH 环境（dsh 自动安装好），按**月或按流量**计费 —— 类似"增值 AI 版 ECS"。

**北极星关联**：完全落地"用户免部署、任何地方浏览器即用 DSH"——用户连机器都省了。

## 3. 需求拆解

### 3.1 用户提出的

① 云端创建（租用）DSH 环境：hub portal 里"创建云主机" → 我们调度云资源 → 自动装 dsh → 出现在用户 host 列表 → 浏览器即用；
② 临时 / 永久两种形态；
③ 计费：按月 或 按流量（见 3.2-② 讨论）。

### 3.2 补充思考（"what else"）

**① 资源供给方式（D1）**
- A. **云厂商 API 代购**（推荐起步）：调阿里云/腾讯云 ECS（或轻量应用服务器）API 创建实例，cloud-init/UserData 自动装 dsh + join hub；我们按厂商账单付成本，用户按我们的价格付。
- B. 自持物理机/私有云：重资产，不推荐起步。
- C. 用户自带云账号 + 一键部署（我们不持有资源）：门槛仍在用户侧，与 09 目标不符；但可作**验证前置**（见 §6）。

**② 计费模型（D2）—— 用户提出"月或流量"，需定**
- 按时间（月租/小时）：简单、可预期；08 订阅表可扩展（rented host = 资源订阅）。
- 按流量：DSH 会话 = 事件流 + 文件传输 + 终端输出，**流量大且难预测**（一次大文件传输可能吃掉月流量）—— **不建议 MVP 做流量计费**。
- 建议：**MVP = 固定规格档位 × 月租（或小时）**，带宽按档位包含（超限限速不额外计费）；"按流量"后置为高级套餐。
- 计量：实例运行时长/生命周期 → 账单；欠费/余额不足 → 停机 → 宽限 → 释放。

**③ 实例生命周期状态机（D3）**
- `provisioning（云厂商 API + cloud-init）→ running（已 join hub，可访问）→ stopping/stopped（停机，数据保留）→ releasing（销毁）→ released`
- 停机 ≠ 释放：停机保留数据（续费可恢复）；释放销毁实例 + 磁盘（**销毁前提示导出工作区**）。
- 临时 env：用完销毁（可设自动销毁时长，如 24h / 7 天）；永久 env：按月续费。
- 失败处理：创建失败（资源不足/脚本失败）→ 自动释放**不收费**；join 失败 → 可重试。

**④ 规格档位（D4）**
- 起步 2–3 档固定规格（如 2C2G / 2C4G / 4C8G），映射云厂商实例规格；价格 = 成本 × 毛利系数（可配）。
- 自定义规格/自定义镜像：后置（MVP 固定档）。

**⑤ 镜像/预装（D5）**
- cloud-init 脚本：装 node + remote-dsh + `rdsh host service install <hub-url> --token <t>`（一行接入）。
- 预装 dsh 依赖（dsh CLI 在 PATH）；可选常用工具链（python/node/git）。镜像维护（OS 更新、dsh 版本更新）是持续运营项。
- 用户自定义预装脚本：后置。

**⑥ 安全与隔离（D6）**
- **单租户实例**（每用户独立 ECS）→ 天然隔离，安全简单（成本高）；容器化省钱但有隔离/资源竞争/逃逸风险 → **MVP 单租户实例**。
- dsh web 只绑 127.0.0.1 + join 出站隧道 → 实例公网零入站（SSH 运维口仅限我们运维 IP）。
- 实例密钥：云厂商密钥对注入（我们持有），供运维/排障；用户不直接 SSH（浏览器即用）。

**⑦ 数据保留与合规（D7）**
- 用户工作区数据在实例磁盘：停机保留、释放销毁；**销毁前明确提示 + 提供导出**（MVP：提示 + 关键文件下载；后置：快照/rsync 引导）。
- 个保法/用户协议：云端数据由我们托管 → 隐私政策/数据删除需覆盖"云端实例数据"；08 的账号删除流程扩展（删账号 → 同时释放其云端实例）。

**⑧ 成本模型与运营（D8）**
- 收入 = 转售差价 + 增值服务费；关注资源利用率（空闲实例可建议休眠）。
- 包月实例闲置也收费（与云厂商一致，简单）；小时计费按实际运行。
- **起步验证**：先手动租 1–2 台实例跑通全流程（创建→join→浏览器访问→销毁），量化成本/毛利，再自动化。

**⑨ 合规不确定点（D9）—— 必须诚实记录**
- **转售云资源**：代购 ECS 转租给用户 → 是否落入"互联网资源协作服务业务（B11）"监管？川 B2 证（08 已核）大概率**不含 B11** → **上线 gate 前置：咨询通管局 + 云厂商转售条款**。
- 若 B11 必要 → 办理（长周期）或调整模式（以"托管服务"名义定价为服务费而非资源转售 —— 边界模糊，需合规确认）。
- 数据存储地域/备案：实例地域选择影响备案与个保法。

**⑩ 与 08 的里程碑关系（D10）**
- 09 **前置依赖 08**（账号/支付/计费/portal 基建）；建议 08（S1–S4）完成后启动。
- 09 范围（用户定案，2026-08-26）：**带 dsh 的云主机转售**（转售 ECS/VM，dsh 预装，用户自带 API key）—— 09a 手动验证 → 09b 固定档计费 + 生命周期 MVP → 09c 自动化/扩展（按流量、自定义镜像、更多规格）；
- **Token 转售拆出**：原"09b + Token 转售"独立立项为 **`10-saas-dsh-token`**（可横切服务自有 host 用户，独立收入线）。

**⑪ 纯浏览器交互（用户定案，2026-08-26）**
- **不提供 SSH/CLI**：用户全程浏览器（登录 portal → 创建/进入云端 DSH → 干活 → 释放），与自有 host 体验完全一致；
- 安全红利：用户无密钥面；运维通道（云厂商密钥对/控制台）仅运营方持有；
- 结论：09 的增量收敛为**实例创建/生命周期 + 计费**；登录/portal/进入/API key 粘贴全部复用 M3–M5 现有能力。

**⑫ API key 模式（D11，用户定案）**
- 09 阶段：**用户自带 key**（DSH 界面粘贴，复用 M4/M5 portal paste-box）—— 零模型成本、零计量、零转售合规；
- **Token 转售（我们/合作方 key 注入）拆出为独立立项 `10-saas-dsh-token`**：模型额度售卖、Token 用量计量、余额体系、转售合规 —— 见 10 文档；
- 09 用户"免自带 key"体验由 10 提供（云端 host 创建时选"用我的 key / 用平台额度"）。

### 3.3 用户旅程（纯浏览器，2026-08-26 用户定案）

```
1. 登录 hub portal（08 账号体系）
2. host 列表：自有 host（办公室/家里）+「云端 DSH」分区
3. 点「创建云端 DSH」→ 选规格（2–3 档）→ 显示计费（xx 元/小时）→ 确认
4. provisioning（30–90 秒：云厂商开实例 + cloud-init 装 dsh + join hub）→ running
5. 点击进入 → DSH 界面 → 首次引导：粘贴 DeepSeek API key → 开始干活
6. 用完：stop（暂停保留）或 release（销毁，提示导出工作区）
```

**复用映射**：登录/portal/host 列表/进入 = M3–M5 现有；API key 粘贴 = M4/M5 portal paste-box（05 已定"API key 由 DSH 界面粘贴/持久化"）；join 接入 = `rdsh host service install <hub-url> --token <t>` 一行；浏览器访问已实测（2026-08-26）。**09 增量 = 实例创建/生命周期 + 计费**。

**细节**：release 前明确提示"工作区将被删除"并引导导出关键文件；创建按钮旁显式显示计费（xx 元/小时，停机不收费或包月）；实例规格 2–3 档固定、国内地域。

## 6. 验证前置（低成本先证伪）

在投入自动化前，先手动验证三点（半天~2 天工作量）：

1. **用户旅程**：手动开一台云实例 → cloud-init 装 dsh + join → portal 浏览器访问 → 销毁 —— 全程体验是否顺；
2. **成本模型**：一台实例月成本（厂商价 + 带宽）vs 建议售价 → 毛利是否成立；
3. **合规一问**：向通管局/云厂商咨询转售边界。

验证通过 → 09a（自动化 MVP）立项；不通过 → 收缩为"用户自带云账号一键部署"（C 方案）或放弃。

## 7. 技术约束备忘

- **复用优先**：账号/支付/计费/portal/join 全部复用 08；`rdsh host service install <hub-url> --token <t>` 一行接入是 cloud-init 的核心；
- **幂等**：实例创建/释放/计费状态机全部幂等；创建失败不收费；
- **协议先行**：新增层 1 API（cloud instance create/list/stop/release + 计量查询）契约先行；
- **成本护栏**：创建实例 = 花钱 → 限流/配额/余额校验前置（复用 08 配额 + 新增余额/信用检查）；
- **依赖**：云厂商 SDK 为合理例外；其余延续零依赖纪律。

## 8. 更大图景：Agent-as-a-Service（Manus 式，2026-08-26 用户提出）

**触发**：用户指出 Manus（云端自主智能体，曾以 ~$2B 与 Meta 谈收购、后因监管拆分由腾讯接盘）做的事与"云端 DSH"同构 —— 我们以 DeepSeek Harness（成熟开源 agent 运行时）+ rdsh（远程访问/云接入）+ DeepSeek 模型（低价国产），**可以少得多的努力达到同等能力**。

### 8.1 Manus 价值拆解 vs 我们的对应物

| Manus 的层 | 我们的对应 | 状态 |
|---|---|---|
| 云端 agent 运行时（自主操作浏览器/工具/文件） | **DSH（DeepSeek Harness）**—— 工具/工作流/插件生态 | ✅ 现成开源 |
| 大模型 | **DeepSeek 模型**（国产、成本低） | ✅ 现成 |
| 云访问/会话 | **rdsh hub + join 隧道 + portal**（浏览器/手机/微信内可用，已实测） | ✅ 已实现 |
| 商业化 | **08 SaaS**（注册/订阅/招行聚合支付） | 🔄 S1–S4 |
| 云端环境租用 | **09 云端 DSH**（cloud-init 一行装 dsh+join） | 💡 本文 |
| **任务驱动 UX**（一句话派活、看进度、拿结果） | ❌ 无 —— 当前 DSH 是交互式工作区 | **缺口（未来 AaaS）** |
| **规模化编排**（环境池/任务调度/并发/自动回收/成本控制） | ❌ 无 —— 09 是"每用户租一台"的 v1 | **缺口（未来 AaaS）** |

### 8.2 结论
- **成立的部分**：agent 运行时 + 模型 + 云访问 + 变现，我们已具备或正在做——Manus 估值中"agent 运行时与云编排"的大头，我们以开源 DSH 低成本获得；
- **不能白拿的部分**（= 未来 AaaS 里程碑的真增量）：任务驱动 UX + 规模化编排 + 可靠性护栏（自主 agent 的工具误用/越权/内容安全——M5 审计/风控可复用为护栏底座）；
- **前置查证**：DSH 工具生态是否支撑"自主浏览网页/操作外部系统"（Manus 招牌能力）—— 决定 AaaS 能力上限；
- **成本/毛利**：模型 API（DeepSeek 低价）+ 云实例 + 带宽 —— 按任务/用量计费模型需早验证（承接 D2）；
- **合作叙事**：开源 DSH 底座 + 便宜国产模型 + 浏览器即用 —— 对阿里云/万国数据等是"云资源批量消费方"，可谈批量折扣/IDC 合作；对投资人是"低成本复刻 Manus 模式"的差异化故事（B11/资质非阻塞，见 §5）。

### 8.3 执行顺序（不改变）
08（变现闭环）→ 09（云环境租用）→ 未来 AaaS（任务驱动 UX + 编排）。大图景是**方向与叙事**，不改变 S1–S4 先行。
