# DSH 0.1.2-rc.1 兼容性核验（remote-dsh）

> **日期**: 2026-09-03
> **对象**: `@deepseek-ai/dsh@0.1.2-rc.1`（npm `next` 通道）与 remote-dsh（gateway/hub/插件）兼容性
> **结论**: **兼容 ✅**——remote-dsh 依赖 DSH 的三个硬契约点在 0.1.2-rc.1 全部保留，无需改动（gateway 协议「永不需要改动」承诺不受影响）

---

## 1. 背景

DeepSeek Harness 于 2026-09-03 发布 `0.1.2-rc.1`（0.1.2 系列首个候选版本）。确认 remote-dsh 与之是否兼容：网关会 spawn `dsh web` 并补丁其前端 client bundle，若 DSH 改动这些接口则需适配。

## 2. 核验范围（remote-dsh 依赖 DSH 的三个硬点）

| # | 依赖点 | remote-dsh 用法 |
|---|---|---|
| 1 | `dsh web` CLI 契约 | gateway spawn `dsh web --port 0 --no-open`（OS 分配端口）|
| 2 | 监听端口打印格式 | gateway 解析 stdout/stderr 的 `dsh web: http://127.0.0.1:<port>` 行 |
| 3 | 前端 client bundle 补丁目标 | `patchLoopbackJs` 匹配 `isLoopbackHostname(pageLocation.hostname)`（`trustE2EEAsLoopback`，老 host 明文 UI 兼容）|

> 另：hub 对 DSH 的 `/api/*` 与 WS（events.mux/events.host）为透明转发，与 DSH 版本契约无关；dsh-web-remote 插件运行于 DSH 的 cordis 宿主。

## 3. 核验方法与证据（实包检查，2026-09-03）

| 依赖点 | 证据 | 结果 |
|---|---|---|
| 1. spawn 契约 | `dsh-web-app@0.1.2-rc.1` `lib/startup.js`：`--port <port>` 注明「pass 0 to let the OS pick a free one」+ `--no-open` 均在；`web` 命令别名保留（`dsh` 包 `lib/bin.js`）| ✅ 保留 |
| 2. URL 打印 | `dsh-web-app@0.1.2-rc.1` `lib/index.js`：`console.log(\`dsh web: ${url} (LAN: ...)\`)` 同格式 | ✅ 保留 |
| 3. 补丁目标 | `dsh-client-connection@0.1.2-rc.1` `lib/client.js` 含 **`isLoopbackHostname(pageLocation.hostname)`**（精确保留，regex 可命中）| ✅ 保留 |
| 附. cordis | 依赖 `@deepseek-ai/cordis` 4.0.1 → **^4.0.2**（补丁级）| ⚠️ 低风险，插件需在 4.0.2 环境冒烟 |

版本号列车：0.1.2-rc.1 全套 `@deepseek-ai/dsh-*` 子包同步升至 0.1.2-rc.1。

## 4. 为何 0.1.2-rc.1 未设为 latest（dist-tag 结论）

```
npm dist-tags:
  latest: 0.1.1-rc.2     ← 稳定线（裸 `npm i @deepseek-ai/dsh` 安装）
  next:   0.1.2-rc.1     ← 0.1.2 候选线
  alpha:  0.1.2-alpha.5
```

- 官方 GitHub release 原文：「作为 **0.1.2 系列的首个候选版本**，本版本汇总了自 v0.1.1-rc.2 以来的主要用户和开发者相关变更」；
- 候选版本（rc）惯例只挂 `next`，待正式 0.1.2 稳定版发布后才会 promote 到 `latest`——**非异常，是发布节奏**。

## 5. 0.1.2-rc.1 变更性质（与本仓库无交集）

全部为 UI/UX/功能面：会话流折叠/宽度/字号、token 用量与耗时显示、回合导航、第三方语言本地化、子代理模型选择、Windows SDK、ACP 补齐、实验性 Inspector / Web Preview、连接状态与自动重连、`send_message` 双向（取代 `report`）等——**无一条触及 web 服务启动、端口打印或 client-connection 补丁目标**。

## 6. 建议

- **测试 DSH 新线**：`npm i -g @deepseek-ai/dsh@next`（= 0.1.2-rc.1）——remote-dsh 兼容已核；
- **生产/默认**：保持 `latest`（0.1.1-rc.2），待官方 promote 0.1.2 稳定再跟；
- 若升级 DSH 到 0.1.2-rc.1：**dsh-web-remote@0.4.0**（cordis 4.0.2 环境）插件面板需冒烟验证一次。
